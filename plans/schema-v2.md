# android.avar.me: сборка мобильных словарей v2

Дата: 2026-09-30. Статус: план без изменения сборки и публикации.
Общий план: [sources](../../sources/plans/schema-v2/README.md).
Команда приложения: [avarme-android](../../avarme-android/plans/schema-v2.md).
Схема: [проект](../../sources/av-ru-schema-evolution-plan.md).

Каталог этого репозитория — android, не andriod.
`scripts/config.py` задаёт входы; `scripts/build_dictionary.py` преобразует
JSONL в SQLite с relations/see_also. На момент изучения этот скрипт совпадал
с iOS-сборщиком; изменения согласовать, не давать форматам разойтись случайно.

## Последний старый выпуск

- Собрать из последнего v1 JSONL, записать хеш входа/коммит sources.
- Опубликовать последний старый пакет и проверить его старым приложением.
- Сохранить существующие latest.json и архивы по package_url. Не менять
  их на v2 и не повышать min_app_version. Старые приложения смогут получить
  последний выпуск позже, но дальнейших редакционных обновлений v1 не будет.
- Не удалять файлы старого канала при деплое/очистке новых сборок.

## Новая сборка

1. Согласовать новый канал `/v2/latest.json` и `/v2/packages/<release>.zip`
   с приложением. Заменить av-ru-вход на согласованный v2 URL sources;
   ru-av пока остаётся прежним.
2. Поддержать literally, links и формы статьи/значений forms_dict.
3. Согласовать JSON внутри SQLite с Kotlin-моделями. Наличие нового
   источника не требует одинакового номера версии JSONL, DB и манифеста.
4. Сохранить поиск, target_id/target_word, уточнения ссылок и literal/comment.
   Решить, сохраняется ли внутренний формат relations/see_also или меняется.
5. Согласовать dictionary_version и min_app_version нового канала,
   совместимый встроенный пакет и скрипт синхронизации assets.
6. Проверить пакет на новой версии Android и процедуру перехода со старой базы.
7. Публиковать новый latest.json только после подтверждения приложения.

## Приёмка

ZIP, SHA-256, metadata и SQLite валидны; формы доступны поиску; ссылки и
буквальные переводы отображаются; старое приложение продолжает получать
последний v1. Проверить обновление поверх старой скачанной базы.
Поля второго этапа (id/hash/cefr/origin) необязательны, остаются в v2 и не
теряются там, где должны передаваться. Будущие исходные id не подменяют
генерируемые мобильные id без согласованной миграции.

Откат нового пакета при монотонных версиях — исправленный совместимый
выпуск с новым номером, не надежда на автоматическую установку меньшего номера.
Архивы старого канала сохраняются, постоянного преобразователя v2 → v1 нет.
